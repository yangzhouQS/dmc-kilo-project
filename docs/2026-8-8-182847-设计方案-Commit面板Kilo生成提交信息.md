# 设计方案：Commit 面板「Kilo 生成提交信息」功能

## 1. 功能概述

在 IntelliJ Commit 面板（底部 Commit Tab）的提交信息编辑区工具栏，
新增一个按钮图标。用户点击后，自动读取**复选框勾选的文件变更内容**，
组装标准化 Prompt 填充到 Kilo Code 对话输入框，等待用户确认发送。

**核心约定**：仅填充输入框，**不自动发送**，与现有 3 个 Action 行为一致。

## 3. 技术方案

### 3.1 API 确认（IntelliJ 2026.1 实测）

| 需求 | API | 来源 jar |
|---|---|---|
| 按钮注册组 | `Vcs.MessageActionGroup` | `intellij.platform.vcs.impl.jar` |
| 获取勾选的变更文件 | `VcsDataKeys.COMMIT_WORKFLOW_UI` → `CommitWorkflowUi.getIncludedChanges()` | `intellij.platform.vcs.jar` |
| 提交信息控件 | `VcsDataKeys.COMMIT_MESSAGE_CONTROL` → `CommitMessageI` | `intellij.platform.vcs.jar` |
| 读取文件旧内容 | `Change.getBeforeRevision()?.getContent()` | `intellij.platform.vcs.core.jar` |
| 读取文件新内容 | `Change.getAfterRevision()?.getContent()` | `intellij.platform.vcs.core.jar` |
| 变更类型 | `Change.getType()` → `MODIFICATION / NEW / DELETED / MOVED` | `intellij.platform.vcs.core.jar` |

### 3.2 完整执行流程

```
用户点击 [Kilo生成] 按钮
  │
  ├─ 1. 获取 CommitWorkflowUi → includedChanges (List<Change>)
  │     └─ 空列表 → 通知"请先勾选要提交的文件"，终止
  │
  ├─ 2. 遍历每个 Change，提取：
  │     ├─ 文件路径（afterRevision?.file 或 beforeRevision?.file）
  │     ├─ 变更类型（NEW / MODIFICATION / DELETED / MOVED）
  │     ├─ 旧代码内容（beforeRevision?.getContent()，可能为 null）
  │     └─ 新代码内容（afterRevision?.getContent()，可能为 null）
  │
  ├─ 3. 组装标准化 Prompt（见 3.3 模板）
  │     └─ 控制 Prompt 总长度（超长截断，避免 token 爆炸）
  │
  ├─ 4. DmcSessionResolver.getSessionManager(project)
  │     └─ null → 通知"请先打开 Kilo 工具窗口"，终止
  │
  ├─ 5. manager.insertPromptText(prompt)
  │     └─ 填充到 Kilo 输入框，焦点移至输入框
  │
  └─ 6. 通知"提交信息 Prompt 已填充到 Kilo"
```

### 3.3 Prompt 模板

```
请根据以下代码变更生成规范的 Git Commit Message（遵循 Conventional Commits 规范）

【变更文件数】：3 个文件
【变更概览】：
  - src/main.ts (修改)
  - src/utils.ts (新增)
  - src/old.ts (删除)

【详细变更内容】：

--- src/main.ts (修改) ---
```diff
// 旧代码
const config = { port: 3000 };

// 新代码
const config = { port: 8080, debug: true };
```

--- src/utils.ts (新增) ---
```typescript
export function formatDate(d: Date): string {
  return d.toISOString().split('T')[0]
}
```

--- src/old.ts (删除) ---
（文件已删除）
```

### 3.4 大文件截断策略

| 文件内容长度 | 处理 |
|---|---|
| ≤ 500 行 | 完整包含 |
| 500 ~ 2000 行 | 仅包含前后各 50 行，中间省略 |
| > 2000 行 | 仅包含文件名和变更类型，不含代码 |
| Prompt 总长 > 8000 字符 | 截断后续文件，追加 `（更多变更已省略）` |

### 3.5 线程约束

- `actionPerformed` 在 EDT 执行（IntelliJ 保证）
- `ContentRevision.getContent()` 可能涉及 VFS 读取 → 用 `ReadAction` 包裹
- `insertPromptText` 操作 UI → 必须在 EDT
- 全流程可在 EDT 内同步完成（数据量小），无需后台线程

## 5. 核心代码结构

```kotlin
class GenerateCommitMessageAction : AnAction() {

    override fun update(e: AnActionEvent) {
        val ui = e.getData(VcsDataKeys.COMMIT_WORKFLOW_UI)
        e.presentation.isEnabled = ui?.includedChanges?.isNotEmpty() == true
    }

    override fun actionPerformed(e: AnActionEvent) {
        val project = e.project ?: return
        val ui = e.getData(VcsDataKeys.COMMIT_WORKFLOW_UI) ?: return
        val changes = ui.includedChanges

        if (changes.isEmpty()) {
            notify(project, "请先勾选要提交的文件", WARNING)
            return
        }

        val prompt = buildCommitPrompt(project, changes)

        val manager = DmcSessionResolver.getSessionManager(project)
        if (manager == null) {
            notify(project, "请先打开 Kilo 工具窗口", WARNING)
            return
        }

        manager.insertPromptText(prompt)

## 6. 异常处理

| 异常场景 | 处理策略 |
|---|---|
| 未勾选任何文件 | 通知「请先勾选要提交的文件」，终止 |
| 文件内容读取失败 | 跳过该文件，继续处理其他文件 |
| Kilo 工具窗口未打开 | 通知「请先打开 Kilo 工具窗口」 |
| insertPromptText 异常 | 通知具体错误信息 |
| 变更文件数 > 20 | 通知「变更文件过多（N 个），仅处理前 20 个」 |
