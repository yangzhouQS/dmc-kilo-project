# RepoWiki 项目知识库 — 架构原理与技术文档

## 一、设计理念

RepoWiki 是一个**双层混合架构**的知识管理系统，利用 Kilo Code 的两个独立扩展层协作：

| 层 | 职责 | 运行进程 |
|---|---|---|
| **CLI 插件**（TypeScript） | AI 交互：System Prompt 注入、工具注册、事件监听 | CLI 子进程（Node.js/Bun） |
| **JetBrains 插件**（Kotlin） | IDE 集成：代码扫描、UI 面板、右键菜单 | IDE JVM |

**核心理念**：CLI 插件负责"大脑"（AI 能力），JetBrains 插件负责"界面"（IDE 交互），两者通过 `.kilo/repowiki/` 文件目录通信。**不修改任何上游源码。**

### 3.2 知识注入流程

```
用户提问 → chat.message Hook
              ↓
     experimental.chat.system.transform Hook
              ↓
     collectKnowledge(wikiBase)
     ├── 读取 knowledge_cards/*.md（最多 3 张，各 2000 字符）
     ├── 读取 memory/*.md（最多 5 条，各 500 字符）
     └── 拼接 + 截断至 6000 字符
              ↓
     output.system.push("## 项目知识库上下文\n...")
              ↓
     LLM 收到的 System Prompt = [原始 prompt, 知识库上下文]
```

### 3.3 记忆保存流程

```
方式 1：用户主动
─────────────────
用户在对话输入: /remember 这个项目禁止使用 any 类型
    ↓
chat.message Hook 拦截
    ↓
saveMemory(wikiBase, "这个项目禁止使用 any 类型", "general")
    ↓
写入 memory/general-1723536000000.md

方式 2：AI 主动
─────────────────
AI 完成任务后决定沉淀记忆
    ↓
调用 wiki-remember 工具 (tag="architecture")
    ↓
saveMemory(wikiBase, 记忆内容, "architecture")
    ↓
写入 memory/architecture-1723536000000.md
    ↓
下次对话 system.transform 自动注入
```

## 四、关键技术实现

### 4.1 CLI 插件加载机制

```
CLI 启动 (kilo serve --port 0)
  ↓
扫描配置目录:
  ├── ~/.config/kilo/plugin/*.ts     (全局插件)
  └── .kilo/plugin/*.ts              (项目插件)  ← repowiki.ts 放这里
  ↓
PluginLoader.load()
  ├── dynamic import(".kilo/plugin/repowiki.ts")
  ├── 调用 plugin(input, options) → Hooks 对象
  └── 注册 Hooks 到内部数组
  ↓
后续每次对话/事件 → 遍历 Hooks 数组触发对应 Hook
```

### 4.2 System Prompt 注入原理

CLI 在构建 LLM 请求时，会依次触发所有 `experimental.chat.system.transform` Hook：

```typescript
// CLI 内部伪代码
const systemPrompts = ["You are Kilo Code..."]

// 触发插件 Hook
for (const hook of hooks) {
  await hook["experimental.chat.system.transform"]?.(
    { sessionID, model },
    { system: systemPrompts }  // 插件修改此数组
  )
}
// systemPrompts 现在包含 ["You are Kilo Code...", "## 项目知识库上下文\n..."]
// 整体发送给 LLM
```

源码位置：`packages/opencode/src/session/llm/request.ts:86`

### 4.3 自定义工具注册原理

```typescript
// 插件返回的 tool Hook
{
  tool: {
    "wiki-generate": tool({
      description: "扫描项目代码结构并生成 Wiki 文档",
      args: { module: tool.schema.string() },
      async execute(args, ctx) { ... }
    })
  }
}
```

CLI 将这些工具与内置工具（read/write/bash）合并，一起发送给 LLM。LLM 看到工具列表后，根据用户意图决定是否调用。

```
内置工具: read, write, bash, edit, ...
自定义工具: wiki-generate, wiki-query, wiki-remember
                ↑
LLM 工具列表 = 内置 + 自定义，LLM 自主决定调用
```

### 4.4 JetBrains 文件监听

JetBrains 插件通过 `BulkFileListener` 监听 VFS（虚拟文件系统）变更：

```kotlin
connection.subscribe(VirtualFileManager.VFS_CHANGES, object : BulkFileListener {
    override fun after(events: List<VFileEvent>) {
        // 检测到 .kilo/repowiki/ 下的 .md 文件变更
        // → 自动刷新 UI 面板
    }
})
```

当 CLI 插件写入新的 Wiki 文档时：
1. 文件系统变更 → VFS 检测到
2. `BulkFileListener` 触发
3. 面板 `refresh()` → 重新读取目录文件列表
4. 用户看到新文档

### 5.2 psi-structure.json 格式

JetBrains `PsiStructureScanner` 生成的 JSON：

```json
{
  "src": {
    "name": "src",
    "totalLines": 14,
    "files": [
      {
        "path": "/project/src/index.ts",
        "name": "index.ts",
        "lines": 3,
        "exports": []
      },
      {
        "path": "/project/src/api.ts",
        "name": "api.ts",
        "lines": 50,
        "exports": ["class ApiClient", "function fetchData", "const BASE_URL"]
      }
    ]
  }
}
```

CLI `wiki-generate` 工具读取此 JSON，结合 AI 推理生成 Markdown 文档。

## 六、Hook 类型签名（从源码验证）

所有 Hook 定义在 `packages/plugin/src/index.ts:222-335`：

| Hook | 签名 |
|---|---|
| `experimental.chat.system.transform` | `(input: {sessionID?, model}, output: {system: string[]}) => Promise<void>` |
| `chat.message` | `(input: {sessionID, agent?}, output: {message, parts}) => Promise<void>` |
| `tool` | `{ [name]: ToolDefinition }` |
| `event` | `(input: {event: Event}) => Promise<void>` |
| `experimental.session.compacting` | `(input: {sessionID}, output: {context: string[]}) => Promise<void>` |
| `tool.execute.after` | `(input: {tool, callID}, output: {title, output, metadata}) => Promise<void>` |

### ToolDefinition 签名（`packages/plugin/src/tool.ts:45-51`）

```typescript
export function tool<Args extends z.ZodRawShape>(input: {
  description: string
  args: Args                                    // Zod schema
  execute(args: z.infer<z.ZodObject<Args>>, context: ToolContext): Promise<ToolResult>
})
```
