# PRD：资源管理器右键「添加到会话 / 添加到新会话」功能需求文档

## 业务目标

在 JetBrains IDE 项目资源管理器（Project View）文件 / 目录的右键上下文菜单，新增两个菜单项：**添加到会话**、**添加到新会话**。
用户选中文件 / 文件夹，右键可直接把目标文件或整个目录批量作为上下文送入 KiloCode AI 会话，免去手动复制文件内容、手动输入`@`引用的操作，快速给 AI 提供项目上下文。

> 触发入口：IDE 项目资源管理器 → 选中文件 / 目录（支持多选） → 右键菜单 → `添加到会话` / `添加到新会话`。
> 
> 

---

## 一、功能详细需求

### 1\. 菜单显示规则

1. **菜单位置**：JetBrains 项目视图（Project View）文件 / 目录右键上下文菜单。

2. 两个 Action ID

    - `kilo.add.to.current.session`，显示文本：**添加到会话**

    - `kilo.add.to.new.session`，显示文本：**添加到新会话**

3. 扩展点：`com.intellij.projectView.popup`，挂载到项目视图右键菜单，`anchor="last"`，放在原生菜单下方，不干扰 IDE 原有功能。

4. 显示约束

    - ✅ 支持选中**单个文件、单个目录；支持多选文件 \+ 目录混合选中**；

    - ✅ 文件：读取文件完整内容作为会话上下文；

    - ✅ 目录：递归遍历目录，过滤忽略文件（`.git`、`node_modules`、`dist`、`build`等），批量加载目录内源码文件；

    - ❌ 无选中条目时，两个菜单隐藏；

    - ❌ 选中虚拟文件、不可读文件，菜单置灰不可点击。

> 菜单排序：两个菜单项相邻展示，“添加到会话” 在上，“添加到新会话” 在下。
> 
> 

### 2\. 两个菜单行为定义

#### 2\.1 添加到会话（添加到当前活跃会话）

1. 获取 IDE 当前 KiloCode 插件**已经存在的活跃会话窗口**；

2. 获取资源管理器选中的文件 / 目录集合；

3. 解析选中资源：文件直接读取文本内容；目录递归扫描，过滤忽略目录，收集源码文件列表；

4. 将这批文件作为**上下文引用附加到当前会话**；

5. 自动激活、展开 KiloCode ToolWindow 侧边面板，切换到当前活跃会话；

6. **行为约定：只追加文件上下文引用，不会自动发送消息，输入框保持为空，用户继续手动输入提问。**

> 效果等价聊天框输入`@文件名`，批量把多个文件加入会话上下文。
> 
> 

> 如果**不存在活跃会话**：执行降级逻辑，自动新建一个会话，再把文件添加进去，弹出 Balloon 提示：`当前无活跃会话，已自动创建新会话并添加文件`。
> 
> 

#### 2\.2 添加到新会话

1. 获取选中的文件 / 目录集合；

2. 解析选中资源，读取文件 / 扫描目录得到文件列表；

3. **全新创建一个空白 Kilo 会话**；

4. 将选中全部文件作为上下文附加至这个全新会话；

5. 自动激活 Kilo 侧边 ToolWindow，切换至刚创建的新会话；

6. 输入框为空，等待用户输入问题，**不自动发送任何 prompt**。

### 3\. 文件 \& 目录处理规则

1. **文件处理**

    - 文本类文件：读取完整文件内容加入上下文；

    - 二进制文件（图片、exe、压缩包）直接跳过，不加载，给出提示；

2. **目录递归扫描规则**
默认过滤以下目录（兼容 gitignore 常见规则）：

    ```Plain Text
    .git, node_modules, dist, build, out, target, .idea, .vscode, __generated__
    ```

3. 文件大小限制：单文件超过阈值（默认 500KB），跳过该文件，气泡提示：`XX文件过大，已跳过加载`。

4. 多选支持：同时选多个文件、多个文件夹，全部合并加入会话上下文。

### 4\. 上下文数据模型

> 和聊天框`@文件`保持完全统一内部数据结构，复用现有上下文组件，保证聊天面板可以看到已附加的文件列表。
> 
> 

- 附加到会话不是把全部文件文本一次性塞进输入框；

- 在会话元数据记录引用的`VirtualFile`列表；

- AI 请求发出的时候，再动态读取文件内容拼装到 LLM 请求上下文；

> 优势：文件修改之后，下一轮对话自动读取最新版本文件，不会使用旧缓存文本。
> 
> 

### 5\. 执行流程（纯文本无图表）

#### 添加到会话流程

1. 用户在项目资源管理器选中一个 / 多个文件、目录，右键点击【添加到会话】

2. 获取选中 VirtualFile 集合，校验文件可读、过滤二进制文件

3. 判断 KiloCode 是否存在活跃会话

    - 存在活跃会话：复用当前会话

    - 无活跃会话：自动新建会话，气泡提示用户

4. 如果选中包含目录：递归遍历目录，跳过黑名单目录、超大文件、二进制文件，得到最终文件集合

5. 将文件集合作为上下文引用追加到目标会话元数据

6. 激活 KiloCode 侧边 ToolWindow，切换至目标会话

7. 聊天面板展示已附加的文件列表，输入框保持空白，等待用户输入问题

#### 添加到新会话流程

1. 用户选中资源管理器文件 / 目录，右键点击【添加到新会话】

2. 获取选中 VirtualFile 集合，校验过滤资源

3. 选中包含目录时执行目录递归扫描过滤

4. 创建全新空白 Kilo 会话

5. 将解析完成的文件集合附加到新会话元数据

6. 激活 KiloCode ToolWindow，切换至刚刚创建的会话

7. 聊天面板展示附加文件列表，输入框空白，等待用户提问

### 6\. 异常兜底逻辑

|异常场景|处理策略|
|---|---|
|选中文件部分无法读取 / 文件被删除|跳过不可读文件，Balloon 提示：`部分文件读取失败，已跳过`，剩余正常文件继续添加|
|全部选中文件均被过滤（全部二进制 / 全部超大文件）|菜单执行后气泡提示：`没有可加载的文本文件，操作结束`，会话不发生变更|
|创建会话失败、Kilo 服务内部异常|右下角 IDE Balloon 错误通知：`添加文件到会话失败，请重试`，流程终止，不抛出崩溃|
|目录遍历数量过多，文件数量超限|提示：`选中目录文件数量过多，仅加载前N个文件`，防止上下文溢出|

### 7\. UI 表现

1. 成功执行：Kilo 侧边面板自动打开，会话头部展示已经附加的文件清单，输入框保持空白；

2. 部分文件被跳过：右下角弹出浅色通知，告知哪些文件被跳过；

3. 失败：红色气泡提示错误信息；

4. 聊天面板中，用户可以手动移除已经附加的文件上下文（复用现有移除文件的交互）。

## 二、技术关键点与扩展点选型

### 2\.1 plugin\.xml 注册扩展点

> 扩展点：`com.intellij.projectView.popup`，Project 视图右键菜单
> 
> 

```xml
<action id="kilo.add.to.current.session" class="xxx.KiloAddToCurrentSessionAction" text="添加到会话">
    <add‑to‑group group‑id="ProjectViewPopupMenu" anchor="last"/>
</action>

<action id="kilo.add.to.new.session" class="xxx.KiloAddToNewSessionAction" text="添加到新会话">
    <add‑to‑group group‑id="ProjectViewPopupMenu" anchor="last"/>
</action>
```

### 2\.2 Action 中获取选中资源

通过`ProjectView.SELECTED_ITEMS`获取项目视图选中对象，拿到`VirtualFile`集合。

```kotlin
// update方法控制菜单是否启用
override fun update(e: AnActionEvent) {
    val selectedFiles = e.getData(ProjectView.SELECTED_ITEMS)
    val hasValidFile = selectedFiles.orEmpty().any { it is VirtualFile && it.isValid }
    e.presentation.isEnabledAndVisible = hasValidFile
}
```

### 2\.3 可复用现有模块

1. 复用现有会话管理服务：会话创建、获取活跃会话；

2. 复用现有的文件上下文数据结构（和`@文件`输入框引用同一套模型）；

3. 复用 ToolWindow 唤起激活逻辑；

4. 复用文件读取、大小校验、二进制文件检测工具；

5. 目录递归扫描：实现黑名单过滤逻辑；

6. IDE 通知：统一使用 Balloon 通知工具。

### 2\.4 线程约束

1. UI 操作（唤起 ToolWindow、更新会话元数据）必须运行在 **EDT 线程 invokeLater**；

2. 文件 IO、目录递归扫描，放到后台 ReadAction / 后台线程执行，**不能阻塞 UI**。

### 2\.5 关键注意事项

1. 不要一次性把全部文件文本直接写入 prompt 输入框；使用会话元数据引用 VirtualFile，请求 AI 的时候动态读取内容，文件修改自动生效；

2. 做好文件数量、文件大小上限，防止一次性加载几百个文件造成上下文爆炸；

3. 目录递归严格过滤黑名单目录，禁止扫描`node_modules`等大型目录，避免卡顿。

## 四、明确非需求范围

1. ❌ **不会自动填充提问 prompt，不会自动发送 AI 请求**，仅附加文件上下文，由用户手动输入问题；

2. ❌ 本次不支持直接右键目录直接提问；只做文件附加到会话；

3. ❌ 不修改磁盘上任何源文件，仅内存会话元数据引用；

4. ❌ 会话关闭之后，附加的文件引用跟随会话生命周期，不做持久化。
