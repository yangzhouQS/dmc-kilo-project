# RepoWiki 待实现功能规划

> 当前版本：v2（基础功能已完成）
> 最后更新：2026-08-09
> 状态：待规划，按优先级分批实现

---

## 一、增量更新（优先级：高）

### 现状
- 文件变更追踪已有（`.meta/changed-files.json`），但无人消费
- Wiki 生成后无法增量更新，只能全量重写

### 待实现

| 功能 | 类型 | 说明 | 预估工作量 |
|---|---|---|---|
| `wiki-diff` 工具 | CLI 插件 | 读取 `changed-files.json` + 对应旧 Wiki，返回需要更新的文档列表 | 2h |
| `wiki-read` 工具 | CLI 插件 | AI 读取已有 Wiki 内容，避免全量重写 | 1h |
| 人工编辑保护 | CLI 插件 | `wiki-save` 检测 `<!-- kilocode-manual-edit-start/end -->` 标记，跳过人工段 | 2h |
| "刷新 Wiki" 按钮 | JetBrains Action | ProjectView 右键 → 读取变更文件 → 触发 AI 增量更新 | 3h |
| 变更列表清空 | CLI 插件 | 增量更新完成后清空 `changed-files.json` | 0.5h |
| 文件哈希比对 | CLI 插件 | `.meta/hashes.json` 记录每个源文件的 hash，精准判断是否变更 | 1h |

### 交互流程（规划）

```
用户右键 → "刷新 Wiki"
  ↓
JetBrains: 扫描变更文件 → 写入 changed-files.json
  ↓
发送 prompt 到 Kilo: "请增量更新 Wiki 文档"
  ↓
AI 调用 wiki-diff → 获取需要更新的文档列表
  ↓
AI 对每个文档:
  ├── wiki-read 读取旧内容
  ├── read/grep 分析变更代码
  ├── 合并新旧内容（保护人工编辑段）
  └── wiki-save 写入更新
  ↓
清空 changed-files.json
```

## 二、知识卡片自动生成（优先级：中）

### 现状
- 知识卡片只能手动创建
- 没有自动提取架构/技术栈/规约的能力

### 待实现

| 功能 | 说明 |
|---|---|
| 架构卡片自动生成 | 分析项目依赖树 + 目录结构 → 生成架构概述卡片 |
| 技术栈卡片自动生成 | 读取 `package.json`/`build.gradle.kts`/`pom.xml` → 生成技术栈卡片 |
| 规约卡片提取 | 扫描 `AGENTS.md`/`CLAUDE.md`/`.editorconfig` → 生成编码规约卡片 |

## 三、多语言知识库（优先级：中）

### 现状
- `detectLanguage` 已支持 zh/en 切换
- 但无法同时维护两套语言的知识库

### 待实现

| 功能 | 说明 |
|---|---|
| 双语并行生成 | 生成 Wiki 时同时输出 zh + en 两份 |
| 语言切换 UI | KiloWiki 面板加语言切换下拉框 |
| 跨语言引用 | 某语言缺失文档时自动回退到另一语言 |

## 四、Git 团队同步（优先级：中）

### 现状
- `.kilo/repowiki/` 可提交到 Git
- 但无合并冲突保护机制

### 待实现

| 功能 | 说明 |
|---|---|
| `.gitattributes` 模板 | Wiki 文件标记为 `merge=union` 避免冲突 |
| 分支隔离 | 不同分支的知识库目录隔离（`.kilo/repowiki/{branch}/`） |
| 合并通知 | `git pull` 后检测知识库变更 → 通知面板刷新 |

### 待实现
